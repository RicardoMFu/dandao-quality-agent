# 开发与协作

## 仓库

私有仓库：`RicardoMFu/dandao-quality-agent`。仓库所有者可在 Settings → Collaborators 添加同组GitHub账号，授予write权限。当前未收到账号名单，尚未邀请。已有权限的成员可直接创建功能分支并发起PR。

建议分工：评分/案例负责`agent/rubric.py`、`prompts/`、`examples/`；后台负责`agent/`与`server.py`；界面负责`web/`。改字段时同步更新测试、示例、提示词与前端。

## 接口

| 接口 | 作用 |
|---|---|
| GET /api/bootstrap | 案例、九维标准、接口配置状态、历史记录 |
| POST /api/run | `{case, mode: rules或llm}`，成功才存机器结果 |
| POST /api/review | 追加复核；必须指定run_id、reviewer、judgment、resolution、reason |
| POST /api/import | 校验1—100条cases并返回相似问法分组 |
| GET /api/export | 完整机器与人工JSON |
| GET /api/export.csv | 逐次运行与最近人工结论汇总 |

字段由Pydantic模型约束，见`agent/schema.py`。来源过期/冲突等规则在`agent/evidence.py`，评分封顶在`agent/rubric.py`。错误模型响应不存为“成功但0分”。

## 接入学校模型

配置`JUDGE_BASE_URL`、`JUDGE_MODEL`、`JUDGE_API_KEY`。base地址由项目提供，不由网页用户输入；服务不提供改写接口。只支持HTTPS或本机HTTP，禁止HTTP跳转。当前发送的数据包括脱敏问答、人工参考正文与标签，接入前由项目确认使用该模型处理这些材料的权限。

超时60秒，无自动重试；响应要求JSON，九维必须完整，分数等级必须合法，正文引用必须存在。接口兼容并不代表效果合格；首次接入应先用内置案例跑通，再用授权的真实问答与人工基准评价。

## 校准与迭代

导出后按run_id连接runs和reviews，可比较逐维等级、风险漏判、来源误判与待核实比例。保留rule_version、prompt_version、model、input_hash、usage与时间。修改规则后对同一输入生成新运行，不覆盖旧评价。当前仅保留对照记录，没有自动修改提示词、模型权重或语料库。

## 本地演示与多人开发

该Demo用于本机运行；Git共享表示源码协作，不表示多人在线共享SQLite。正式共享服务需要学校批准的部署环境、身份认证、权限控制和数据策略，再替换本地HTTP入口。当前监听127.0.0.1，Host和Origin校验、JSON请求限制、静态路径白名单、CSP、CSV公式转义为本机原型提供基本保护。

隐私识别不是完备DLP；自动脱敏只覆盖常见号码与密钥模式。仓库只提交测试输入、原始移交代码和提取规则，不提交真实运行数据库、密钥或学校问答日志。
